# Function — 무엇을 만드는가

화면 목록, 역할별 권한, 사용자 흐름. **`docs/screen-api-map.md` 의 결정(7절)을 화면 단위로
풀어 쓴 것**이다 — 그 문서가 "왜 이렇게 정했나" 라면, 이 문서는 "그래서 무엇을 만드나" 다.
화면 ID 는 Stitch 프로젝트 `projects/9433856227347358698/screens/{id}` 를 가리킨다.

> **여기 적힌 화면은 전부 만들어졌다.** 이 문서는 "무엇을 만드는가" 의 정의로 남기고,
> **화면별 실제 연결 상태(어떤 API 를 쓰는지, 무엇이 아직 준비 중인지)는
> [`docs/screen-api-map.md`](../docs/screen-api-map.md) 1~4절을 본다.** 아래 표의
> "API 없음" 표시는 [이슈 #107](https://github.com/expo-platform-team4/expo/issues/107) 로
> 모아 추적한다.

**범위 밖** — 배너 3화면([이슈 #103](https://github.com/expo-platform-team4/expo/issues/103)),
`Expo Exhibition Service Auth Flow` 화면. 만들지 않는다.

## 1. 역할과 권한

```
비로그인   공개 화면만. 로그인·가입·박람회 목록·상세·비회원 주문 조회
MEMBER    + 예매·결제, 마이페이지(주문·티켓)
CLIENT    + 주최사 포털 전체 (박람회·부스·모집공고·정산·체크인)
ADMIN     + 관리자 전체 (승인·심사·정산 확정)
```

CLIENT 와 ADMIN 은 겹치는 경로가 있다 — 백엔드가 `/api/client/**` 를
`hasAnyRole("CLIENT","ADMIN")` 으로 열어 두기 때문이다(체크인이 그 경우다. Spec.md 3절 참고).

## 5. 체크인 흐름 — 디자인이 없어 새로 정의한다

`docs/screen-api-map.md` 7-3 이 정한 전제.

```
1. 결제 완료 → 발권 → SMS 로 /tickets?token= 링크 발송 (발권·SMS 는 구현됨, 결제는 미연동)
2. 구매자가 모바일 브라우저로 링크를 열어 QR 화면을 본다 (구현됨)
3. 박람회 개최자(CLIENT)가 자기 박람회 체크인 화면에서 QR 을 스캔한다
4. 카메라가 안 되면 티켓 코드를 손으로 입력해도 같은 결과를 낸다
```

**현장 스태프 계정이 없다.** CLIENT 본인 계정으로 스캔한다 — 백엔드가 이미 이 전제로
`ExpoHostVerifier` 를 두고 있다(자기 박람회만 스캔 가능).

**화면 셋:**

```
/client/check-in            오늘 체크인 현황 (입장 완료 수 / 전체)
/client/check-in/scan       카메라로 QR 스캔 + 코드 수동 입력 폼을 같은 화면에서 전환 가능하게
/client/check-in/history    체크인 이력 목록. 필터(성공/실패) 지원
```

**카메라 제약** — 브라우저 카메라는 HTTPS 또는 `localhost` 에서만 열린다. 배포 환경에서
HTTP 로만 서빙하면 스마트폰에서 안 열린다(`~/Downloads/expo-docs/09-DEPLOY-HTTPS.md` 참고).
그래서 **코드 수동 입력을 스캔의 열등한 대체가 아니라 동등한 경로로** 노출한다 — 카메라가
막혀도 시연이 끊기지 않는다.

## 6. SMS 인증 — 현재 상태

일반회원 가입(`7eb82549`)의 휴대폰 인증 단계는 **실제 문자를 보내지 않는다.** 서버가 인증번호를
DEBUG 로그로만 남긴다(`PhoneVerificationService.java:78`). 화면은 정상 흐름대로 만들되,
**로컬에서는 고정 테스트 인증번호 `123456` 을 그대로 입력하면 통과한다**(같은 파일 125행).
실연동은
[이슈 #104](https://github.com/expo-platform-team4/expo/issues/104)로 D 갈래가 이어받는다 —
프론트 쪽에서 할 일은 없다.

## 7. 없는 API 를 만난 화면 — 처리 원칙

[`docs/screen-api-map.md`](../docs/screen-api-map.md) 4절이 정리한 것들이다. 화면 자체는 만들되:

1. **API 부재를 화면에 명시한다** — "준비 중" 배지 등 눈에 보이게. 조용히 빈 목록으로
   두면 버그처럼 보인다
2. **이슈로 남긴다** — 새로 발견한 API 부재는 `mcp__ccd_session__spawn_task` 또는
   `gh issue create` 로 기록하고 이 문서에 링크를 추가한다
3. **막지 않는다** — 그 화면 하나 때문에 전체 작업을 멈추지 않는다. 다음 화면으로 진행
